# Croi Firmware

Firmware for Croi, the Ogma core flight-computer board.

## Build Targets

```bash
pio run -e stm32f072c8t6
pio test -e sil
```

Target purpose:

- `stm32f072c8t6`: flight firmware for the current Croi MCU target.
- `sil`: native software-in-the-loop tests.

## Runtime Tasks

- State machine task: owns flight-state progression.
- CAN task: exchanges Ogma stack frames.
- Logger task: writes flight and secondary data to external flash.

Task stacks and queues use static storage. `croi_status` reports stack high-water headroom and remaining RTOS heap for hardware-in-the-loop checks.

## Sensors And Storage

The current firmware instantiates:

- `LSM6DSO32` IMU,
- `MS5607` barometer,
- `MX25L128` flash driver.

The current hardware schematic shows W25Q128-class flash; the driver accepts both MX25 and W25Q128 JEDEC IDs.

## Flash Logging

Croi uses `FlashLogger` records:

- `FlightData`: core state, prediction, barometer, IMU data.
- `SecondaryFlightData` v2: GPS, airbrake commands, and Pleasc command/status/ack events.

Ogma Console can read the flash log over SWD through `ogma_flash_mailbox`, then parse and export the records locally.

The logger publishes used, free, and mission-required byte counts through `croi_status`; `ogma_flash_mailbox` publishes the readable log length. Host reads stop at written data instead of scanning the full 16 MiB device.

Persistent records begin only after the FSM enters `POWERED`. Logging continues through flight and the configured post-landing window. Before entering `READY`, Croi reserves worst-case capacity for one core record and, when enabled, one remote CAN record per sample period. A short reserve keeps the logger faulted and the FSM in `CALIBRATING`, while the SWD mailbox remains operational for data recovery.

## Host Interface

SWD-readable symbols:

- `ogma_board_identity`
- `croi_status`
- `ogma_flash_mailbox`

`croi_status` reports IMU/baro/CAN/logger initialization, watchdog progress, and flash capacity for bench probing.

The state machine remains in `CALIBRATING` until the IMU, barometer, CAN, and flash logger are healthy and the filter has valid calibration samples. Any IMU or barometer initialization failure halts before flight tasks begin.

Flash mailbox reads are read-only, require an SWD bench lease, and are rejected during active flight states. The temporary flash-wipe image is bench-only and must be restored to the normal image by Ogma Console.

No UART is required for host readout.

## Libraries

- `braiteoiri`: IMU, barometer, flash, buzzer drivers.
- `comheadan`: CAN, SPI, I2C interfaces and shared data structs.
- FreeRTOS/CMSIS wrapper.
- Eigen for native/SIL math paths.

## Deployment Policy

- Airbrakes use independently locked deploy-after-liftoff and stow-after-liftoff times plus leased Lamh commands.
- Drogue command is issued after Croi enters `DROGUE` and Pleasc reports the channel armed.
- Main command is issued after Croi enters `MAIN` and Pleasc reports the channel armed.
- `CROI_MISSION_DROGUE_DELAY_MS` is the minimum time spent in `DROGUE` before main transition; Ogma Console labels it accordingly.
- Pyro commands use a mission tag, rolling sequence, command tag, critical TX queue, bounded retry until fired confirmation, ACK/status feedback, and flash event logging.
- External RBF remains mandatory for Rev1.

## Mission Manifest

`include/croi_mission_config.h` is generated by Ogma Console when a mission is locked. It supplies the liftoff threshold, recovery mapping, deploy/stow times, bounded airbrake parameters, sample period, minimum flight logging window, post-landing duration, and remote-CAN policy. The firmware exposes its manifest magic, schema, CRC, and calculated capacity in `croi_status` so the Console can verify the flashed image.

The default checked-in manifest disables airbrakes and both pyro channels. Ogma Console generates, builds, flashes, and verifies mission-specific manifests by CRC.
